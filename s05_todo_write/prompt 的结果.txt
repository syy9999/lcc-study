### Refused — 46 of 47 warnings are false positives

**`RUF001/2/3` (46 hits):** flags CJK fullwidth punctuation `：，（）；` in docstrings, comments, and strings as "ambiguous unicode." But this codebase's comments are **entirely Chinese**, where fullwidth punctuation is *correct typography*. "Fixing" these would replace `：` with `:` and wreck the prose — and `RUF001` even hits user-facing error messages like `f"text 必须是 str，得到 {type(text).__name__}"`. Ruff's own docs say to disable these rules for non-English codebases. **I left all 46 alone.** Autofixing them is exactly the trap this exercise invites.

**`I001` (1 hit, in `test_utils.py`):** ruff wants to delete the blank line between `import pytest` and `from demo_pkg import ...`. That blank line is **PEP 8-correct** — it separates third-party from first-party imports. I proved it's a config-less false positive: `ruff check --select I --config "lint.isort.known-first-party=['demo_pkg']"` → **All checks passed**. Applying the autofix would merge the two groups and make the code *worse*, so I did not.
