### 2026-11-23：新增五层上下文压缩

今天新增了上下文压缩模块。核心思路是按照代价从低到高逐层处理：优先缩减局部的大块工具输出，再整理历史消息，最后才调用外部模型总结整个历史。

1. **新工具结果限额**：针对新产生的 `tool_result`，压缩其中的大块内容，直到总字符数低于 `char_limit` 上限。先在工具结果进入后续对话时控制体积，避免单次大输出迅速撑满上下文。
2. **历史消息外存**：当历史消息队列超过设定数量时，保留最开始的 3 条消息以保存任务起源，并保留最近的 46 条消息；将中间的消息保存到外部，在队列中用一条包含存储路径的信息替代，使消息队列保持在 50 条以内。
3. **已读工具结果压缩**：遍历历史中的 `tool_result`，排除尚未被模型读取的结果，从最早的结果开始依次压缩。优先回收旧输出占用的空间，同时让模型有机会先看到新返回的内容。
4. **全量工具结果压缩**：进一步放开前一层的筛选限制，对所有 `tool_result` 按块大小从大到小压缩，包括未读结果。在上下文压力更大时，优先释放大块输出占用的空间。
5. **模型总结历史**：调用外部模型，将所有历史消息压缩为一条摘要，同时将完整历史保存到外部。作为代价最高的一层，用模型提炼继续任务所需的信息，并保留完整记录以供后续查阅。

这里同时控制了两个维度：工具结果的字符体积，以及历史队列的消息数量。将内容移到外部后，上下文通过路径保留查阅入口；第五层还会额外引入模型调用成本，因此放在最后。

### 配套改动

- 新增压缩工具及对应处理逻辑，让 LLM 可以主动调用工具压缩上下文，与自动压缩机制配合。
- 重新设计 agent loop 的控制流，协调模型请求、工具执行和压缩步骤之间的衔接。
- 对齐各层策略、压缩工具与调用方的参数，明确各自的触发条件、处理范围和返回结果。

实际实现比五层策略的描述更复杂：还需要协调未读工具结果的处理、历史外存后的路径替换，以及压缩后 loop 如何继续运行。压缩时也需要维护 `tool_use` 与 `tool_result` 的配对完整性，避免整理历史后消息结构失效。
